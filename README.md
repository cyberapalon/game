# Lumen Hollow

An original, playable 2D metroidvania vertical slice made with **Godot 4.7.2 and typed GDScript**. You are a seed-lantern keeper in an abandoned underground conservatory. Find the windseed in the east, learn its air dash, then carry its light back to the home lantern along the upper route.

The slice contains one handcrafted location, fifteen solid platforms, one patrolling moss walker, a five-point health system, a windseed checkpoint, death/recovery, a route map, a completion screen, and pause/restart controls. All character art, architecture, plants, particles, and sound recipes are original and generated by Godot code. There are no external game assets, plugins, or runtime dependencies.

## Play in a browser

The debug build is exported to `build/web/index.html`. From the repository root:

```bash
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/web
```

Open **http://localhost:8000** in a browser with WebGL 2.0 support. With VS Code Remote SSH, forward port **8000** in the Ports panel and open the forwarded URL on your local computer. Click the game to focus the keyboard and enable audio. Keep the server terminal open. Serve the entire `build/web` directory; opening the HTML through `file://` will not work.

The existing Web preset retains `variant/thread_support=false` and `variant/extensions_support=false`. Rendering uses Compatibility / WebGL 2.0, and the build requires no COOP/COEP headers. The game also runs directly with `godot --path .` or F6/F5 in the editor.

## Controls

| Action | Keys |
| --- | --- |
| Move | A / D or Left / Right |
| Jump | Space, W, or Up; release early for a short hop |
| Strike | J or X |
| Dash | Shift or K, after collecting the windseed |
| Pause / resume | P or Escape; the pause screen also has a Continue button |
| Restart expedition | R; resets health and progression |
| Mute / unmute | M |
| Gentle motion | Q; disables camera shake and hit-stop, and stops plant sway |

Walk east and use the mossy steps to cross the broken causeway. The moss walker has three health points and an amber warning before its lunge; strike from a short distance or jump over it. Climb the eastern steps and touch the floating windseed. It restores health and activates a checkpoint. Jump and dash left onto the upper route, then jump and dash across the wide central gap. Follow the carved arrows back to the home lantern. Touching the lantern completes the prototype.

Dash freezes vertical velocity for 0.18 seconds, grants damage immunity, and is available once per airborne interval with a 0.55-second cooldown. Landing restores the air dash. Damage grants one second of immunity and applies knockback. Falling costs health; death restores full health at the last checkpoint. The acquired ability and defeated enemy survive death during the current expedition. Reloading the page or restarting begins a new expedition.

## Build and validation

```bash
# Import resources and verify scripts/scenes.
godot --headless --path . --editor --import

# Behavioral integration checks using real Godot physics and input events.
godot --headless --path . --fixed-fps 60 tests/gameplay_smoke.tscn

# Optional style checks using the already installed gdtoolkit.
gdlint common entities levels ui tests
gdformat --check common entities levels ui tests

# Export the single-threaded browser debug build.
mkdir -p build/web
godot --headless --path . --export-debug "Web" build/web/index.html
```

The smoke scene checks movement/braking, variable jump height, coyote time, jump buffering, every required platforming segment, attack overlap and damage immunity, enemy defeat, ability acquisition, dash immunity, the ability-gated gap, checkpoint recovery, progression after death, and completion. Failures return a nonzero exit code. Headless runs skip audio synthesis because they have no audio output; the browser build includes all synthesized audio.

## Project layout and tuning

- `project.godot`: main scene, autoloads, 1280 x 720 canvas, Compatibility renderer, 60 Hz physics, collision layer names.
- `entities/player/`: reusable CharacterBody2D scene and controller; exported movement tuning, buffered input, native Area2D attack, procedural character drawing.
- `entities/enemy/`: reusable moss walker with patrol, windup, lunge, rest, and stun states.
- `common/`: damage data, reusable health component, session progression, bounded CPU particle effects, original synthesized audio, and the original project icon.
- `levels/conservatory/`: main scene, authored platform layout, reusable stone platforms, and parallax backdrop.
- `ui/`: health signals, objective, route map, hints, pause/completion overlays, and buttons.
- `tests/`: headless behavioral smoke scene; no testing addons required.

Movement metrics: 285 px/s run speed, 670 px/s initial jump velocity, 1550 px/s² gravity, about 140 px measured jump height, and roughly 245 px full running-jump range. Required ascents are 90–100 px high. The upper return gap is 340 px wide and needs the 880 px/s dash. Coyote time is 0.11 seconds and jump buffering is 0.14 seconds. Collision shapes stay at their natural scale; only the drawn character squashes and stretches. Camera smoothing, decaying shake, brief real-time hit-stop, afterimages, and short particle bursts provide feedback.

This is a short keyboard-controlled prototype for desktop browsers. Touch/gamepad support, persistent saves between browser sessions, additional rooms, and desktop/Steam exports are not implemented. Browser audio starts after a user gesture; changing tabs pauses the game, with explicit resume on return. The debug Web engine download is approximately 37 MiB before HTTP compression. Validation on software-rendered Chromium does not establish performance on all target devices.

See [ASSET_PROVENANCE.md](ASSET_PROVENANCE.md) for the asset inventory. The existing setup and export preset are retained; ordinary feature work does not run `setup.sh`.

## Development environment (Ubuntu ARM64 VM)

Minimal repository setup for Godot 4.7.2, Codex CLI, VS Code Remote SSH, and browser preview. The VM stays isolated from macOS; no GUI, Docker, database, or JavaScript game runtime is required.

## One-time VM setup

Ubuntu Server 26.04 (ARM64) in UTM, with a sudo-enabled regular user and an SSH connection from VS Code on macOS:

```bash
chmod +x setup.sh
./setup.sh
```

Setup installs: official Godot editor CLI, single-threaded and threaded Web export templates, Node.js 24 LTS, Codex, Context7, selected Godot/game-dev skills, GitHub CLI, Git LFS, gdformat/gdlint, ShellCheck, FFmpeg, ImageMagick, and basic utilities. The official Godot export-templates archive is ~1.3 GB; sufficient free disk space and network access are required. Downloads are checked against the official SHA512 release file.

Setup asks for GitHub and Codex authorization only when required. It will not overwrite existing `~/.codex/config.toml`. By default, a newly generated Codex config grants full access within the disposable VM; avoid keeping sensitive credentials there.

Reconnect VS Code Remote SSH after setup. Install recommended extensions from the workspace (`.vscode/extensions.json`). Godot Tools is configured to launch a headless language server from the VM; the desktop Godot editor is optional.

## Build and view on macOS

After Codex has generated a working Godot project (`project.godot` exists):

```bash
# Import/validate resources using the headless engine.
godot --headless --path . --editor --import

# Build the browser version.
mkdir -p build/web
godot --headless --path . --export-debug "Web" build/web/index.html

# Serve over SSH port forwarding (keep this terminal open).
python3 -m http.server 8000 --bind 127.0.0.1 --directory build/web
```

In VS Code Ports, forward `8000` if it wasn't forwarded automatically. Then open **http://localhost:8000** in Chrome/Brave on macOS. Game changes require re-export and page refresh; this is not Next.js hot reload. The default Web export is single-threaded, so a simple local HTTP server works without special COOP/COEP headers.

## Optional Godot MCP plugin

Godot MCP is **not required** for the first playable prototype. Once `project.godot` exists, you can add a third-party MIT-licensed editor bridge (inspect the project changes before committing):

```bash
npx --yes @srdarkx/godot-mcp@latest init . --client codex
npx --yes @srdarkx/godot-mcp@latest doctor .
```

Restart Codex after adding the project-local MCP configuration. Live editor operations require the Godot editor/bridge running; file editing, headless validation, and Web export work without MCP. In a VM without a GUI, full live screenshot/editor features may not be available. Do not assume the MCP can see a browser running on the Mac.

For Windows/macOS/Linux release builds, add desktop export presets and their matching templates, validate on actual target systems, integrate Steamworks, and include Godot and asset license notices. You do not need to change engines.
